# Wire-format compatibility

ESPressio Serializable treats wire-format compatibility separately from the C++ API version.

## Native Binary

The native Binary archive starts with the bytes `45 53 50 42` (`ESPB`) followed by a one-byte wire-format version. Version **2** is the current format. A reader MUST reject a different binary wire version rather than guessing its layout.

Within wire version 2, encoded node tags, integer widths, little-endian scalar encoding, object child ordering, and property names are compatibility-significant. Changes to any of these require a new wire-format version.

## CBOR

CBOR output uses standards-compatible definite-length maps/arrays and primitive CBOR values. Compatibility is defined semantically: a payload generated by an older supported release must deserialize to the same object state in a newer release, subject to declared schema migrations.

## JSON

JSON compatibility is semantic rather than byte-for-byte. Property ordering and whitespace are not guaranteed. Canonical property names, aliases, `__schemaVersion`, enum string mappings and schema migrations define compatibility.

## Compatibility policy

* Patch releases MUST NOT intentionally break any current wire format.
* Minor releases MAY add readable representations and schema capabilities but MUST retain readers for current test vectors unless a wire-format major/version byte changes.
* Native Binary incompatible layout changes MUST increment its embedded wire version.
* Test vectors under `tests/vectors/` are immutable once released. New versions add new vectors rather than editing old ones.
